# Trip Planner - Agent Instructions

## Project Objective

Build a practical AI-powered trip planning application using Python, LangGraph and external APIs.

The application should help users plan trips, discover destinations and places, understand weather conditions, convert currencies and manage estimated travel expenses.

The project should prioritize functional features, clean architecture, reliable API integrations and a meaningful AI workflow over unnecessary complexity.

## Core Development Principles

- Build incrementally. Do not implement the entire application in one pass.
- Keep the architecture modular, readable and maintainable.
- Avoid unnecessary abstractions, overengineering and excessive dependencies.
- Use LangGraph for meaningful orchestration, state management and workflow control.
- Do not introduce RAG, vector databases, embeddings or document retrieval systems unless explicitly requested in a future phase.
- Do not replace LangGraph with another orchestration framework without approval.
- Keep external API integrations separate from graph logic.
- Do not duplicate business logic across graph nodes, tools and UI.
- Prefer straightforward solutions over clever or unnecessarily complex ones.

## Architecture

- `app.py` is responsible for the user interface.
- `main.py` is responsible for application entry point or execution orchestration, as appropriate.
- `src/graph/` contains LangGraph state, nodes, graph construction and prompts.
- `src/tools/` contains external API integrations and travel-related utility operations.
- `src/config/` contains configuration and settings.
- `src/utils/` contains reusable helper functions.
- `tests/` contains automated tests.

Do not move files, introduce additional architectural layers or restructure the project without a clear reason.

## LangGraph Guidelines

- Use a clearly defined state schema.
- Keep graph nodes focused on one responsibility.
- Keep API calls out of unrelated graph nodes where possible.
- Use conditional edges only when they provide meaningful workflow control.
- Avoid creating unnecessary nodes merely to make the graph appear complex.
- Keep prompts centralized in `src/graph/prompts.py` when appropriate.
- Handle failures, missing inputs and API errors gracefully.
- Ensure graph execution can be understood and debugged.

## API Integration Guidelines

- Use legitimate external APIs for real-world information.
- Keep API integrations isolated within appropriate modules.
- Never hardcode API keys, secrets or credentials.
- Read credentials from environment variables.
- Provide an `.env.example` file containing placeholder values.
- Validate API responses before using them.
- Handle timeouts, failed requests, rate limits and unavailable data.
- Do not fabricate live weather, place information, exchange rates or other external data.
- Clearly distinguish live API data from AI-generated suggestions.

## Code Quality

- Write clear, readable Python code.
- Use type hints where appropriate.
- Avoid unnecessary classes and abstractions.
- Use descriptive names.
- Keep functions reasonably small and focused.
- Avoid broad exception handling unless errors are appropriately handled or logged.
- Do not silently suppress errors.
- Avoid unnecessary dependencies.

## Security

- Never expose API keys or sensitive configuration in the UI, logs or repository.
- Never commit `.env`.
- Validate user inputs.
- Do not execute arbitrary code generated by the language model.
- Treat external API responses and user inputs as untrusted data.

## Testing

- Add tests for important functionality.
- Mock external API requests during unit tests.
- Do not require real API credentials to run basic tests.
- Test error handling and invalid inputs where appropriate.
- Run relevant tests before declaring a feature complete.

## Workflow for Coding Agents

Before implementing a feature:

1. Read this file.
2. Read `docs/PROJECT_SPEC.md`.
3. Check `docs/ROADMAP.md` to understand the current phase.
4. Inspect the existing code before changing it.
5. Identify the files that need modification.
6. Explain the implementation approach briefly if the task involves substantial changes.

While implementing:

- Work only on the requested phase or feature.
- Avoid unrelated changes.
- Do not overwrite working functionality without justification.
- Do not add dependencies without explaining why they are necessary.
- Do not invent requirements.

After implementing:

1. Summarize the changes.
2. List files created or modified.
3. Explain important architectural decisions.
4. Report tests performed and their results.
5. Mention known limitations.
6. Identify the next logical step without implementing it automatically.

Do not proceed to the next development phase unless explicitly instructed.
